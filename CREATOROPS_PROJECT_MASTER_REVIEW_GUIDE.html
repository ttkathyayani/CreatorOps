1. Executive Summary & Problem Statement

The Industry Problem: In digital marketing, creator operations are broken across unorganized channels (WhatsApp, Slack, Google Drive). Creators miss brand guidelines, client approvals cause critical scheduling delays, and agencies lack structured version auditing.

The CreatorOps Solution: CreatorOps provides a centralized, multi-tenant cloud SaaS with:

  • Client & Campaign Portfolios: Centralized budgeting, deliverables tracking, and client management.
  • 7-Stage Content Production State Machine: Strict gating from Draft to Final Publishing.
  • Two-Tier Approvals: Internal agency manager review followed by external brand client sign-off.
  • Embedded AI Agents: Autonomous script audits, concept brainstorming, feedback clustering, and executive reports.
  • Zero-Trust Multi-Tenancy: Complete row-level tenant isolation per Workspace.

CreatorOps models are organized into 9 relational entities enforcing foreign key integrity:

[Workspace] 1 ── ∞ [Membership] ∞ ── 1 [User]
     │
     └── 1 ── ∞ [Client]
                  │
                  └── 1 ── ∞ [Campaign] 1 ── ∞ [CampaignMetric]
                                  │
                                  └── 1 ── ∞ [ContentItem]
                                                  ├── 1 ── ∞ [ContentVersion]
                                                  ├── 1 ── ∞ [Approval]
                                                  └── 1 ── ∞ [Asset]
Model Key Fields & Constraints Business Purpose
Workspace name, slug (unique), description Represents an isolated organization/agency tenant boundary.
Membership user, workspace, role (Admin, Manager, Creator, Client) Role-Based Access Control link. Enforces unique_together = ("user", "workspace").
Client workspace, name, contact_email, brand_guidelines Brand client account. Stores guidelines ingested by AI Script Review.
Campaign client, title, budget, status, start_date, end_date Marketing initiative grouping deliverables and financial budget.
ContentItem campaign, creator, platform, script_body, caption, status Core deliverable undergoing the 7-stage production workflow.
ContentVersion content_item, revision_number, script_snapshot, created_by Immutable version snapshot providing historical audit trails.
Approval content_item, reviewer, decision, comment, timestamp Audit record of manager or client sign-off or change requests.
Asset content_item, file, filename, s3_object_key, size_bytes Media files (videos, thumbnails, storyboards) uploaded to deliverable.
CampaignMetric campaign, metric_name, metric_value, recorded_date Numerical telemetry (Impressions, Clicks, Conversions, Engagement).

6. AI Agent Framework & Mathematical Heuristics

Architecture: All agents inherit from agents/base.py:BaseAgent and implement a standardized run(data) -> dict interface. This decouples the agent logic from the web views.

1. Script Review Agent (ScriptReviewAgent):

  • Speaking Rate Pacing: duration_seconds = round((word_count / 130) * 60). Flags short-form scripts > 150 words (-15 pts).
  • Call-to-Action (CTA) Audit: Checks presence of keywords (subscribe, link in bio, save, comment). Missing CTA = -20 pts.
  • Opening Hook Audit: Inspects first 20 words for curiosity drivers (why, stop, secret, how, ?). Missing hook = -15 pts.
  • Brand Compliance: Parses client brand guidelines and penalizes forbidden words (-15 pts each).

2. Content Ideas Agent (ContentIdeasAgent):

  • Generates platform-tailored creative concepts, hooks, and formats based on target audience, industry, and campaign goal.

3. Approval Summary Agent (ApprovalSummaryAgent):

  • Clusters disparate feedback comments into 5 operational categories (Hook & Pacing, CTA, Visuals, Branding, Copywriting) and creates a prioritized revision checklist.

4. Campaign Report Agent (CampaignReportAgent):

  • Calculates Completion Rate %, Average Engagement Rate %, and Cost Per Acquisition (CPA = Budget / Conversions), outputting an executive narrative summary.

9. Top 20 Review & Viva Defense Questions & Answers

Q1: What architectural pattern does CreatorOps follow?
CreatorOps implements the Model-View-Template (MVT) pattern in Django alongside Domain-Driven Design (DDD), cleanly partitioning logic across 9 independent modules.
Q2: How is Multi-Tenancy implemented and secured?
We use Row-Level Tenant Isolation centered on the Workspace model. Every query is filtered by request.workspace via our @workspace_required decorator, preventing cross-tenant leakage.
Q3: What are the 4 user roles in your RBAC system?
ADMIN (full agency control), MANAGER (campaigns, internal reviews), CREATOR (scripts, drafts, AI checks), and CLIENT_REVIEWER (external client portal sign-off).
Q4: How does your Content Production State Machine work?
Content moves through 7 strict states: draft → pending_manager → pending_client → approved → scheduled → published. Rejections transition items to changes_requested.
Q5: How does content versioning prevent tampering?
Whenever copy changes, ContentItem.create_version() creates an immutable ContentVersion snapshot with an incremented revision number and timestamp. Old versions are never edited.
Q6: Are your AI agents using external APIs or local logic?
They currently use deterministic heuristic and NLP rule engines inheriting from an extensible BaseAgent. They can be connected to OpenAI, Gemini, or Claude by simply updating the run() method.
Q7: Why did you choose WhiteNoise for static files?
Django's default static handler is insecure for production. WhiteNoise serves compressed, hash-fingerprinted static assets directly through the WSGI layer with high-performance cache headers.
Q8: How did you handle Vercel's read-only filesystem with SQLite?
In config/settings.py, when VERCEL is detected, Django automatically copies the bundled db.sqlite3 to the writable /tmp/db.sqlite3 path, preventing read-only database crash errors.
Q9: What happens when a brand client requests changes?
The status changes to changes_requested, an Approval record is logged, and the ApprovalSummaryAgent extracts the revision feedback into a prioritized action checklist for the creator.
Q10: How are media uploads handled?
Through a dual-storage abstraction in assets/storage.py: when configured, files upload directly to AWS S3 using Boto3; otherwise, they store in Django's local media directory.
Q11: What is the purpose of your custom Context Processor?
workspaces/context_processors.py injects active_workspace, user_role, and memberships into every template automatically, eliminating repetitive queries in views.
Q12: Why is CSRF configuration needed for Vercel?
Django blocks cross-origin POST requests by default. Adding https://*.vercel.app to CSRF_TRUSTED_ORIGINS allows legitimate Vercel form submissions while protecting against CSRF attacks.
Q13: How does your Workspace model handle duplicate names?
In Workspace.save(), a slug generation loop checks for existing slugs and automatically appends an incremental counter (e.g. agency-1, agency-2).
Q14: How are REST APIs structured alongside template views?
DRF's DefaultRouter manages API endpoints under /api/ (returning JSON for clients, campaigns, and content), while Django template views render HTML on main URL paths.
Q15: How does the calendar view work?
It queries deliverables where due_date__isnull=False, ordering them chronologically and displaying color-coded platform and status badges on an editorial timeline.
Q16: What database constraints protect data integrity?
We use unique_together on Client (workspace + name) and Membership (user + workspace) to prevent duplicate clients or dual memberships.
Q17: What speaking speed formula does your Script Review Agent use?
It assumes a standard conversational speed of 130 words per minute: duration = (words / 130) * 60, flagging short-form scripts over 150 words.
Q18: How does your CSS design system adapt to mobile?
static/css/style.css uses responsive CSS Grid and Flexbox with a breakpoint at 768px, collapsing the 260px sidebar into a stacked mobile layout.
Q19: How do you seed test data?
Via custom command python manage.py seed_demo_data, which creates 4 distinct user accounts, 3 clients, 3 campaigns, 5 deliverables, and metrics in an atomic script.
Q20: What are potential future enhancements?
Direct social media publishing via Meta Graph & YouTube APIs, LLM-powered script auto-rewriting, and Stripe subscription billing tiers.
