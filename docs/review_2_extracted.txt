1. SYSTEM ARCHITECTURE
CreatorOps is architected as a three-tier web application structured around the Model-View-Template (MVT) pattern and RESTful application programming interfaces.
Figure 1: High-Level Three-Tier Architecture of CreatorOps
1.1 Client Tier (Presentation)
The client interface is rendered through responsive server-side HTML5 templates utilizing CSS variables for styling. It provides operational screens for workspace
configuration, client brand records, marketing campaigns, content drafting, and approval queues. External clients and automated tools interact via JSON-based REST
endpoints over HTTPS.
1.2 Application Tier (Business Logic)
The application tier is powered by Python 3.12 and Django 6.1. It manages routing, tenant isolation, session validation, and content state transitions. A Django REST
Framework (DRF) layer exposes ModelViewSets for programmatic operations. In addition, an internal rule-based agent module (agents/) provides automated checks on
creator scripts—measuring word count, estimated speaking duration, hook keyword presence, and brand safety compliance. WhiteNoise serves static assets directly from the
WSGI application layer.
1.3 Data Tier (Persistence)
Persistent relational data is stored in PostgreSQL for production deployment, with SQLite supported for local development. Binary assets (images, documents, and videos) are
managed with support for Amazon S3 object storage via boto3 and django-storages.

7. AUTHENTICATION AND ROLE-BASED ACCESS CONTROL
The system implements a four-tier Role-Based Access Control (RBAC) model integrated with multi-tenant data boundaries:
Password Protection: Passwords are stored as salted PBKDF2-SHA256 hashes.
Session Isolation: Sessions are validated with CSRF protection on all state-modifying requests.
Tenant Boundaries: The active workspace is resolved per request. Database operations automatically filter by workspace ID to ensure tenant data
isolation.
Role Definitions:
1. Admin: Global control over workspace settings, members, and roles.
2. Manager: Client brand setup, campaign creation, and primary draft approvals.
3. Creator: Content drafting, script versioning, and asset uploads.
4. Client Reviewer: Read-only access to campaign deliverables with final approval sign-off.
8. CORE MODULES IMPLEMENTATION SUMMARY
Content Lifecycle State Machine: Programmatically manages content transitions across 7 stages: draft → pending_manager → pending_client
→ approved → changes_requested → scheduled → published.
Revision Snapshots: Every script or caption change generates an immutable ContentVersion record, maintaining a complete audit trail.
Automated Script Analysis: The script review module checks text against word count limits, spoken duration pacing, hook keyword placement in the
opening sentence, and forbidden brand terms.
