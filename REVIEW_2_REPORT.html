01 System Architecture

CreatorOps implements an enterprise-grade Three-Tier Cloud-Native Architecture grounded in the Model-View-Template (MVT) design pattern coupled with a high-throughput Django REST Framework (DRF 3.18) API subsystem:

Figure 1.1: CreatorOps Three-Tier Cloud Architecture with Integrated AI Agent Engine and Object Storage

Tier 1: Client & Presentation Layer

  • Web UI: Server-side rendered Django HTML5 templates featuring a curated Black-and-Yellow design system (#111111, #1C1C1C, #FACC15), completely responsive on desktop, tablet, and mobile browsers.
  • REST API Clients: Microservices, mobile endpoints, and testing harnesses consuming serialized JSON over HTTPS.

Tier 2: Business Logic & Application Layer

  • Django 6.1 WSGI Engine: Manages core workflows, multi-tenant workspace routing, session validation, and state machine transitions.
  • AI Agent Engine (agents/): Autonomous Python agent modules executing automated script reviews, hook brainstorms, approval summaries, and performance metric digests.
  • WhiteNoise Static Engine: High-performance WSGI middleware handling compression (Gzip/Brotli), cache headers, and static bundle delivery.

Tier 3: Persistence & Storage Layer

  • Relational Database: Managed Cloud PostgreSQL (Neon/Supabase) via dj-database-url with transactional ACID isolation and connection pooling.
  • Cloud Object Storage: AWS S3 integration via boto3 / django-storages for scalable video, audio, and graphic asset hosting.

02 Cloud Deployment Architecture

CreatorOps is architected for seamless cloud-native execution on the Vercel Global Serverless Edge Platform:

Figure 2.1: Serverless Edge Cloud Ingestion, Managed PostgreSQL Integration, and S3 Storage Pipeline

Execution Pipeline & Cloud Mechanics:

  1. Anycast Edge Ingestion: Requests arrive at Vercel Anycast edge locations where SSL/TLS termination and DDoS mitigation are handled automatically.
  2. Serverless WSGI Execution: HTTP requests route directly to Python 3.12 Serverless functions executing config/wsgi.py with sub-second spin-up times.
  3. Static Asset Delivery: Vercel's global CDN caches and serves bundled CSS, JavaScript, and branding assets directly from edge points of presence.
  4. Serverless Database Adapter: To support ephemeral execution environments, CreatorOps features dynamic database fallback to local writable scratch space (/tmp) during zero-configuration deployments, while seamlessly binding to cloud-hosted PostgreSQL instances when DATABASE_URL is provisioned.

03 Database Schema Design

The relational schema is normalized to Third Normal Form (3NF), comprising 9 core entities designed around tenant isolation:

Entity Name Primary Key Foreign Keys & Relations Key Attributes & Constraints
Workspace id (BigInt) None (Root Tenant Entity) name, slug (Unique), description, created_at
Membership id (BigInt) user_id → User, workspace_id → Workspace role (ADMIN, MANAGER, CREATOR, CLIENT_REVIEWER), unique_together=(user, workspace)
Client id (BigInt) workspace_id → Workspace name, contact_email, industry, brand_guidelines, unique_together=(workspace, name)
Campaign id (BigInt) client_id → Client title, objective, target_audience, budget, status (PLANNED, ACTIVE, COMPLETED)
ContentItem id (BigInt) campaign_id → Campaign, creator_id → User title, platform (IG, YT, TikTok, LinkedIn), script_body, status (7-state finite state machine), due_date
ContentVersion id (BigInt) content_item_id → ContentItem, created_by → User revision_number, script_snapshot, caption_snapshot, unique_together=(content_item, revision_number)
Approval id (BigInt) content_item_id → ContentItem, reviewer_id → User decision (APPROVED, REJECTED, CHANGES_REQUESTED), comment, timestamp
Asset id (BigInt) content_item_id → ContentItem, uploaded_by → User file, filename, s3_object_key, size_bytes
CampaignMetric id (BigInt) campaign_id → Campaign metric_name, metric_value, recorded_date

04 Entity-Relationship (ER) Diagram

The following ER diagram maps the cardinalities and relational constraints among the system entities:

Figure 4.1: Entity-Relationship Diagram displaying 1:N relations, cascade rules, and uniqueness constraints

Relational Cardinalities:

  • Workspace → Membership (1:N): An agency workspace contains multiple enrolled team members.
  • Workspace → Client (1:N): A workspace manages brand records for multiple client companies.
  • Client → Campaign (1:N): Each client sponsors one or more marketing campaigns.
  • Campaign → ContentItem (1:N): A campaign comprises multiple creative content items across channels.
  • ContentItem → ContentVersion (1:N): Every edit spawns an immutable, sequentially indexed version record.
  • ContentItem → Approval (1:N): Multi-tier audit logging of internal manager and external client review decisions.
  • ContentItem → Asset (1:N): Multiple raw or rendered media assets attached to each deliverable.

07 Authentication & Multi-Tenant RBAC

Security is enforced through a multi-layered defense-in-depth model:

  • Cryptographic Password Storage: Implemented via PBKDF2 with SHA-256 (390,000 hashing rounds).
  • Session Hardening: HTTP-only cookies, SameSite=Lax, and mandatory CSRF token validation on all mutating requests.
  • Multi-Tenant Middleware: workspaces.context_processors.active_workspace automatically isolates data views based on the user's active session workspace.
  • Role-Based Access Control (RBAC): Four distinct operational roles:
    1. Admin: Complete organizational control, user invitation, workspace configuration.
    2. Manager: Client CRM, campaign creation, tier-1 content approvals.
    3. Creator: Script drafting, asset uploads, revision creation, AI assistant access.
    4. Client Reviewer: Read-only access to campaign deliverables with tier-2 sign-off authority.

08 Core Modules Implementation

All suggested functional modules from the syllabus are fully operational in the codebase:

  • Authentication & Workspace Module: Supports self-registration, default workspace instantiation, and membership switching.
  • Content Production Engine: Implements a 7-stage state machine (draft → pending_manager → pending_client → approved → scheduled → published) preventing unauthorized phase skips.
  • Approval Engine: Dedicated review inbox with side-by-side revision diffs and feedback loops.
  • AI Agent Suite: 4 specialized agents implemented in Python: ScriptReviewAgent, HookBrainstormAgent, ApprovalSummaryAgent, and PerformanceReportAgent.
  • Cloud Asset Storage: Support for raw video/image ingestion with automatic size formatting and cloud storage keys.
